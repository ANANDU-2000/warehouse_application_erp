# 1.7 — UI/UX Wireframe Analysis Plan (Desktop-first)

## Method (how each page doc will be built — grounded, not guessed)

For every screen, I open the actual `.dart` file(s) and extract:

| What | Where it comes from in code |
|---|---|
| Layout skeleton (top→bottom, left→right) | `Column`/`Row`/`Stack`/`Scaffold`/`AppBar`/`Expanded`/`Flexible` order |
| Sizes | `SizedBox(width:, height:)`, `width:`/`height:` props, `AspectRatio`, `Container(constraints:)` |
| Position/spacing | `Padding(EdgeInsets...)`, `Gap`, `mainAxisAlignment`, `crossAxisAlignment` |
| Breakpoints (desktop vs tablet vs mobile) | Compared against `core/design_system/hexa_responsive.dart` constants (e.g. `kShellRailMin`) |
| Buttons | `ElevatedButton`/`TextButton`/`IconButton`/`FilledButton` — label, icon, `onPressed` handler name (tells us the action, not just the look) |
| Fields | `TextFormField`/`DropdownButtonFormField`/etc. — `decoration.labelText`, `hintText`, `initialValue`, `validator`, `keyboardType` |
| Navigation | `Navigator.push`/`context.go`/`onTap` targets in `core/router/` |

If a value is computed at runtime (e.g. dynamic width from `MediaQuery`) rather than a fixed literal, the doc says `Runtime-computed — not a fixed value` instead of inventing a number.

## Per-page doc template (one file per page — this is the `plan.md` structure)

```
# Screen: <name>
Route: <path from core/router/>
File(s): <dart file path(s)>

## Purpose
1-2 sentences, from code + README context.

## Desktop layout (≥ kShellRailMin)
[Rail | Body] — or full-bleed if no rail
Top→bottom skeleton with real spacing/size values from code.

## Tabs / Sub-tabs (if any)
Tab 1: <name> — file: ...
  Sub-tab 1.1: ...

## Fields (table)
| Field | Type | Position (layout order) | Size | Default | Required | Validation |

## Buttons (table)
| Button | Icon | Position | Action (handler) | Enabled/disabled condition |

## Navigation out of this screen
Where each button/tap goes.

## Loading / Empty / Error states
What renders in each, from code.

## Unknowns
Anything not resolvable from static code.
```
